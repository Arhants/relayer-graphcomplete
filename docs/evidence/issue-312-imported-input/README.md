# Issue #312 imported-input checkpoints

Issue #312 explicitly requires imported inputs to follow conversation chronology and duplicate occurrences within one consuming turn to produce a structured rejection. The product rules are recorded in the PRD's “Node-authored interaction input” section. This slice does not claim the separate user-visible rejection notice acceptance criterion.

| Product promise or boundary | Real production seam checkpoint |
| --- | --- |
| A presenting occurrence must belong to an earlier imported turn | `imported_submitted_input_requires_an_earlier_presenting_turn` imports an earlier answer plus otherwise-valid same-turn and later-turn answers; it checks receipt reasons and the surviving graph projection. |
| Duplicate scope is one consuming turn and exact occurrence | `imported_duplicate_input_occurrence_drops_only_extra_answer_per_turn` checks a valid first answer, a duplicate with a distinct submitted-input ID, a separate valid occurrence, and reuse of the same occurrence in another consuming turn. |
| Invalid values do not reserve an occurrence | The duplicate scenario submits an invalid answer first, then the valid answer for the same occurrence, then a duplicate; only the validated answer is retained. |
| Ordinary export stays canonical; import staging defers duplicate and prior-source inventory decisions to graph-core | `conversation_export_contract` asserts ordinary export validation still rejects duplicate occurrences. `ConversationExportValidator::new_for_import` is invoked only by `ConversationImportStager`; ordinary construction and decoding remain strict. The stage/publish fixture exercises duplicate, same-turn, later-turn, and unresolved-source submissions while the hostile corpus confirms malformed IDs, duplicate child IDs, invalid snapshots, and noncanonical ordering still fail before state is staged. Sabotaging the stager policy wiring makes the real HTTP test fail at POST with `duplicate_submitted_input_occurrence`. |
| Rejected children cannot supply snapshots to non-input authored actions | `rejected_child_snapshot_cannot_poison_non_input_action_materialization` exercises real HTTP stage/publish/re-export with claimed navigate, invoke, and response-root IDs. Each receipt drops the child while accepted text, a valid input sibling, and authored non-input action survive. Sabotaging the legacy action-ID filter restores the 422 publish failure. |
| Legacy payload-less input actions remain readable without invalid-first snapshot poisoning | `invalid_legacy_child_snapshot_does_not_poison_a_later_valid_answer` proves a self-invalid exact-occurrence candidate cannot override the later self-valid candidate. Existing provenance/value regressions preserve the fallback needed when an old payload-less input action has only a rejected child. The fallback is restricted to IDs that name authored payload-less input actions. |
| A self-valid, chronology-valid child for a different source occurrence cannot choose the legacy action snapshot over an exact sibling | `wrong_occurrence_legacy_snapshot_cannot_poison_exact_sibling` submits a conflicting SingleSelect snapshot from the earlier materialized root/layer/action but claims an existing root as the source node, then submits the exact Text sibling. The forged child is rejected because that node did not author the action; the exact sibling must survive. The chronology-valid focused test passes, and removing only occurrence membership makes it fail with both children rejected. Logs: `wrong-occurrence-chronology-valid-green.log` and `sabotage-occurrence-membership-chronology-valid.log`. The historical `sabotage-occurrence-membership.log` was run against the older chronology-invalid fixture and is not evidence for this checkpoint. |
| A reused payload-less action is inventoried under its presenting layer, not its authored source layer | `reused_legacy_input_uses_presenting_layer_for_snapshot_preference` imports I1 with action X on node N/layer A, I2 reusing X/N in B while preserving `source_layer_id=A`, and I3 with the genuine B Text child before a self-valid forged A SingleSelect child. The real GraphDatabase materializer must retain the genuine answer and reject only the unreachable A child. This differs from the wrong-node checkpoint: here node/action are identical and only presenting-vs-authored layer provenance is adversarial. |
| A self-valid same-turn or future-turn child cannot select a legacy snapshot before chronology rejects it | `same_turn_legacy_snapshot_cannot_poison_later_answer` and `later_turn_legacy_snapshot_cannot_poison_later_answer` each put a conflicting, self-valid SingleSelect child before a later exact Text sibling. The presenting turn position used for preferred snapshot selection matches the chronology validator's `interaction_turn_positions` boundary. Both pre-fix cases reproduced two skips instead of one; both focused cases pass with the guard, and disabling only that guard makes the same-turn case fail. Logs: `same-turn-chronology-poison-red.log`, `later-turn-chronology-poison-red.log`, `same-turn-chronology-poison-green.log`, `later-turn-chronology-poison-green.log`, and `sabotage-chronology-snapshot-selection.log`. |
| V2 assets compose with recoverable submitted inputs through the real import route | `mixed_v2_assets_and_recoverable_inputs_survive_http_publish_and_strict_reexport` is an external-runtime integration: its test setup builds the `graph-client`, `visual-assets`, and `harness-host` npm workspaces and launches a real Node host. The HTTP POST stages the import; the subsequent first HTTP PUT reaches the graph-server visual-assets bridge and real `@relayer/harness-host` validator during publication, followed by strict-decoded re-export. It checks the exact authored package and association, one matching content record/digest, the precise rejected-child receipt, and both distinct valid input siblings. |
| Hostile V2 asset records remain atomic while recoverable children are present | `mixed_v2_asset_failures_reject_staging_and_clean_up_with_recoverable_inputs` is also an external-runtime integration whose setup builds the same npm workspaces and launches the real Node host. Its malformed POST variants are rejected by the app import staging reader at content-push (corrupt and duplicate digest), turn-push (missing content and mismatched association), or finish (unreachable digest); they do not invoke the host validator and therefore are not negative host-validator proof. Each POST removes product staging, and the route does not begin graph materialization until a subsequent PUT. |
| Receipt propagation, rejected-answer exclusion, and rejected-only publication behavior | `duplicate_imported_input_is_reported_after_publish_and_absent_from_reexport` observes the HTTP stage receipt, publish receipt, and re-export: five invalid answers receive structured reason codes while two valid distinct answers remain. `rejected_imported_input_is_reported_and_absent_from_reexport` and `accepted_turn_with_only_rejected_input_is_cleaned_up_before_publish` cover standalone rejection and rejected-only cleanup. |
| Accepted action and value authority remains exact | Existing `imported_submitted_input_provenance_must_be_one_exact_accepted_occurrence` and `imported_submitted_input_value_must_satisfy_the_accepted_action` checkpoints remain in place. |
