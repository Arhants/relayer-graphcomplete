## 1. The palette in one paragraph

A cool grey poster card (`#D9DCD9`, K8's exact ground) is the light canvas under lighter green-grey chrome; floating
white cards (prompt, inspector, composer, share cards) sit on it exactly as in B. **Cocoa** (`#725345`, K8's exact ink)
is everything you touch and select: primary buttons (Download, Approve always, Retry, Copy), the comment badge, links,
the selected-row and current-turn bars, the selection ring and the authored sequence stickers; in dark it lifts to
`#7C5C4E` for fills and to latte `#ECC8B8` for text, bars and the ring. **Bubblegum pink** (`#DE5276`, K8's exact accent)
is live work: the running arc, running badge, Running pill, "Running" caption, sidebar Running mark, and Send, the
control that starts it (§5.2); in light it deepens to `#D43064` so the 3px arc holds 3.2:1 on the grey. **Mint** (`#80D497`, K8's success hue) appears
only when GraphComplete accepts (pill, stamp, turn-row chip), replacing the parent's lime. Failure is a brick
(`#A93800`) in light and K8's coral (`#FE8160`) in dark, never next to the pink.

## 4. Node-family colours (B's type channel: a solid 28px disc carrying a white or ink `#1B1B17` icon)

Re-searched with the Gen-1 rules (`research/tmp/final-brief-cat.mjs`, brief §3.3) by `families.mjs` against **this**
palette's reserved colours, both themes: disc ≥ 3:1 on the pill fill and on the canvas; icon (white or ink) ≥ 4.5:1 on
the disc; ΔE_OK ≥ 10 from every reserved colour (cocoa accents, ring and latte, pink running marks and text, every
danger token, warning, mint); hue ≥ 30° from the interaction hue (cocoa 45) **and from the running hue (pink 8)**, ≥ 20°
from danger (40 / 36), warning (75) and success (152); families ≥ 20° apart, maximising min(ΔE/15, CVD/8).

H-specific choices, all recorded in `families.mjs`:
- **Pink gets the interaction gap (30°)**: in B the running badge is a solid disc of the same shape as a family disc, so a
  pink family would impersonate running (the palette-space card's F4 `#970054` / `#FF74AC` did). In the parent the
  running colour was the interaction colour, so it had this gap for free.
- **Global search in per-family hue windows** around the parent's slots, so the scene keeps its reading (F1 violet,
  F2 blue, F3 teal, F4 mustard → olive, F5 magenta, F6 indigo). The unconstrained search (`--free`) put a pink-magenta
  family at h336 and scored lower (0.885).
- **Light disc lightness floor 0.36 and chroma floor 0.07** (Gen-1 used C ≥ 0.1): discs must stay ≤ ~L0.6 to hold 3:1
  on the grey canvas, where sRGB teal cannot reach C 0.1. A 0.40–0.42 floor scored 0.87–0.92 of report 08's targets
  (`work/fam-compare.png` shows the four candidate sets as real pills); 0.36 scores 1.02, and its two darkest discs (F2
  navy, F4 olive) still read as their hue on the white pill.
- The parent's open finding "dark F1 and F6 sit ≈21° apart" is fixed: 27° apart, ΔE 16.3+ everywhere.
- **Light F4 Systems lifted to `#4A5700` (round 2).** Round 1 kept `#2D4600` (L0.36) as an accepted residual; at 1× it
  read as an ink bullet (ΔE 16.7, 1.64:1 vs `--text`) in H4's legend and as a near-black disc on H3. `#4A5700` (L0.43,
  C0.10, h119) passes every family rule above (white icon 7.91, 7.74 on the pill, 5.72 on the grey canvas, light/dark
  hue drift 9.9°); vs `--text` it is ΔE 23.2, 2.19:1. The light set's smallest pair becomes F3/F4 15.1 (was F2/F3
  15.3), still over report 08's 15. The blocker round 1 named was the authored Khaki series: with `#4A5700` fixed, no
  light series-4 member at any hue holds CIEDE2000 ≥ 20 from it (`work/r2/f4-khaki.mjs`, 0 rows), and holding 20 caps
  the lift at L0.395 (`work/r2/f4-joint.mjs`), too little to fix the ink read. So the authored family gate became a
  floor of 15 with 20 as the target (§6): light Khaki moves 0.7 ΔE_OK to `#7D7842`, 15.3 CIEDE2000 / 13.9 OKLab from F4.

## 5. Decisions and risk fixes

### 5.1 Gene R (accent rationing) and gene Q (running ink) — recorded call

B's gene R: one rose does interaction, selection and running; lime appears only on acceptance. K8's semantic plan
splits them: cocoa = interaction and selection, pink = live work. **H keeps K8's plan** (the Gen-2 brief: keep the
palette's plan unless it contradicts R; this is the one place it does, and it is the point of K8). Gene Q ("running ink
= the accent") still holds, because K8's accent *is* the pink. It resolves the parent's stated risk ("rose running and
rose selection share one hue"): ring vs running arc is now ΔE 19.8 light / 26.6 dark (parent: 0). R's second half is
kept: acceptance keeps a colour of its own that appears only when GraphComplete accepts (mint instead of lime).

### 5.2 Colour routing block (the one change outside the token blocks)

The parent's components tie running text to `--accent-text` and Send to `--accent-solid-alt`, because in B one rose did
both. A token-only swap would draw the Running pill, the "Running" caption and the sidebar Running mark in cocoa (the
selection colour) and Send in cocoa, leaving pink only on a 90° arc and a 16px badge, so K8's accent would barely be
visible. `kit.css` is therefore the parent's `components.css` **unchanged** plus `routing.css`, five colour-only rules:
`.b-status.is-running`, `.b-node.is-running .b-node-cap`, `.b-mark.is-running` → `--running-text` (+ `--running-soft-bg`),
`.b-badge.is-running` glyph → `--running-ink`, `.b-send` → `--running` + `--running-ink`. No geometry, no new
components.

**Send stays pink (round-1 call).** The critique asked whether a control should wear the live-work colour. K8's own
plan puts the pink on "the running arc and the Send fill" (`K8.md` §1), and Send is the one control whose press starts
live work, so the pink marks where a run begins; every other control (primary buttons, Approve always, Retry, Copy,
Download, links, selection) stays cocoa, and Stop / Stopping stay neutral. The H1 header says "pink for live work and
the Send that starts it" instead of "only live work". H6 has one board rule re-pointed the same way (`.s-run`, the running glyph in the turn popover).
